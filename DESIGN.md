# DESIGN.md — визуальная система «Коплю — Трачу — Помогаю»

> Версия: 1.0 · Прочитать вместе с `CONTEXT.md` до написания компонентов.
>
> Это **предлагаемая цифровая дизайн-система** по мотивам презентации НЦФГ, а не утверждённый официальный брендбук. После получения реальных бренд-материалов обновить токены и графику.

## 1. Визуальная идея

**«Тёплая игровая финансовая грамотность»**. Дружелюбная, ясная, выразительная цифровая среда, в которой ребёнку 6–10 лет хочется разбираться с собственной копилкой, а родителю легко помогать. Интерфейс должен выглядеть как **качественное современное детское приложение**, а не банковский личный кабинет, шаблонный dashboard или мультфильм из случайных эмодзи.

Характер:
- яркий, но **не кислотный**;
- современный, но **не стерильно-корпоративный**;
- игровой, но **не перегруженный**;
- уютный, тактильный, узнаваемый;
- с понятной иерархией и крупными интерактивными зонами.

**Эталон впечатления:** «дорого сделанный детский edtech с продуктовым UX»; не «неоновый fintech для трейдеров».

## 2. Цветовая система (точные рабочие токены)

Отсылка к физической копилке и презентации: **бирюзовый / розовый / жёлтый** — три постоянных цвета категорий.

| Токен | HEX | Использование |
|---|---|---|
| `--canvas` | `#FBF7ED` | основной тёплый фон |
| `--surface` | `#FFFFFF` | карточки, формы, панели |
| `--surface-soft` | `#F6F1E6` | спокойные секции |
| `--ink` | `#26343B` | основной текст, заголовки |
| `--ink-muted` | `#65727A` | пояснения, подписи |
| `--line` | `#E6E2D9` | тонкие границы |
| `--primary` | `#C82D70` | главный CTA, акцент бренда |
| `--primary-hover` | `#B52463` | hover/focus related |
| `--save` | `#159FAA` | **Коплю** — бирюзовый |
| `--save-soft` | `#DDF3F3` | фон секции «Коплю» |
| `--spend` | `#DD568A` | **Трачу** — розовый |
| `--spend-soft` | `#FBE6EF` | фон секции «Трачу» |
| `--help` | `#DFAF20` | **Помогаю** — жёлто-золотой |
| `--help-soft` | `#FFF2C6` | фон секции «Помогаю» |
| `--success` | `#287C5C` | подтверждения |
| `--error` | `#B8424B` | ошибки |
| `--focus` | `#287C94` | контрастный focus ring |

Важные правила:
- Цвет категории сохраняется на всех экранах: «Коплю» = бирюза, «Трачу» = розовый, «Помогаю» = жёлтый.
- На светло-жёлтых карточках использовать **тёмный текст**, не белый.
- Цвет — **не единственный** маркер: есть название категории, иконка, текстовое описание.
- Контраст текста проверить по WCAG; при необходимости адаптировать оттенки, **не нарушая семантики**.
- Одновременно в одном экране — максимум 1 ведущий цвет для CTA и 2–3 семантических цветовых акцента. Избегать «радуги ради радуги».

  --primary: #c82d70;
  --primary-hover: #b52463;
  --save: #159faa;
  --save-soft: #ddf3f3;
  --spend: #dd568a;
  --spend-soft: #fbe6ef;

Компоненты shadcn должны использовать эти токены (или их преобразование в соответствующие Tailwind-переменные), а не случайные дефолтные цвета.

## 3. Что категорически не делать

- **Никакого свечения / glow / neon**, кислотных цветов и светящихся рамок.
- **Никаких сильных теней**, длинных «плавающих» shadow, bloom, многослойного glassmorphism.
- **Никаких обильных градиентов.** По умолчанию использовать **solid fills**. Один очень мягкий декоративный градиент в hero допустим только если он реально улучшает композицию и не похож на неон.
- Не применять яркие размытые разноцветные пятна, чрезмерный blur, «aurora backgrounds», glow behind cards.
- Не делать app в стиле тёмного крипто-дашборда, SaaS-CRM или игровой слот-машины.
- Не использовать серые прямоугольники/таблицы как основной визуальный язык детского экрана.
- Не заполнять интерфейс десятками эмодзи, случайными 3D-иллюстрациями, анимированным конфетти при каждом клике.
- Не допускать анимационного шума, раздражающих автоматических циклов, мигания, пульсации кнопок и бесконечного «прыгания» элементов.
- Не жертвовать удобством чтения ради модного оформления.

## 4. Композиция и UI-грамматика

### Радиусы, линии, тени

- Карточки: `20–28px`, приоритет ~`24px`.
- Кнопки: `14–18px`, основные CTA можно делать pill-like.
- Поля: `12–16px`.
- Границы: `1px solid var(--line)` или более контрастная аккуратная линия для интерактива.
- Тени: минимальные, примерно `0 2px 10px rgba(38,52,59,.05)`; для большинства блоков можно **без тени**.
- Важные карточки могут иметь тонкую, уверенную обводку и едва заметное смещение декоративной подложки, но не тяжёлые 3D-эффекты.

### Сетка

- Mobile-first от **360px**; рабочая ширина 390/430px.
- Контент на мобильном: 16–20px боковых отступов, gap 12–20px.
- Небольшие вертикальные блоки с воздухом, крупные понятные заголовки.
- На desktop: центрированный контейнер до ~1180–1240px; можно использовать сетку 12 колонок, а детскую зону оставить выразительной, не растягивая один виджет на всю ширину.
- На мобильном **нижняя навигация** для основных пользовательских сценариев (не больше 4–5 пунктов); на desktop адаптация в sidebar или верхнее меню.
- **Sticky/nav** не должны закрывать контент; учитывать safe-area на iPhone.

### Типографика

- Headings: **Nunito ExtraBold** или другой качественный округлый кириллический шрифт без чрезмерной мультяшности.
- Body/UI: **Nunito Sans** или **Manrope** с хорошей кириллицей.
- Fallback: системный sans-serif; не ломать интерфейс, если веб-шрифты недоступны.
- Крупные заголовки на детских страницах ~28–36px mobile, до 42–48px hero desktop.
- Основной текст обычно **16–18px**, вспомогательный не мельче 13–14px; детские кнопки — 16px+.
- Короткие предложения; говорить «Добавить деньги», а не «Инициализировать транзакцию».
- Финансовые значения крупные и читаемые; табличные цифры там, где важно сравнение.

## 5. Дизайн главных экранов

### Приветствие
- Ясный headline о трёх привычках и связи с настоящей копилкой.
- Выразительная **собственная** иллюстрация/композиция трёх секций/персонажей-пазлов (если официальных исходников пока нет, создать простые оригинальные SVG/формы).
- Кнопка «Посмотреть демо», понятное пояснение для родителей.
- Не превращать welcome в рекламный лендинг на 12 секций — основная цель быстро начать.

### Детская копилка / главный экран
- Hero с приветствием и коротким вопросом «Что сделаем сегодня?».
- **Три тактильные карточки** категорий — важнейший визуальный элемент приложения.
- Для категорий использовать отличающиеся иконки/маленькие иллюстрации, а не только разные цвета.
- Понятные суммы, 1 главный CTA «Добавить действие».
- Прогресс накопительной цели, аккуратная иллюстрация цели, задание недели ниже.
- Без dense таблиц и финансовых графиков на главной детского режима.

### Добавление операции
- Bottom sheet / dialog в зависимости от устройства, управляемое через Radix/shadcn.
- Шаги максимально короткие: тип действия → секция → сумма → подтверждение.
- Большие поля и кнопки; понятно, что происходит с реальными деньгами.
- Подтверждение — дружелюбный toast или inline state, не бесконечное конфетти.

### Цель
- Имя цели, нужная сумма, сохранено, сколько осталось.
- Иллюстрированный прогресс, семантически корректный `Progress`.
- Лёгкий мотивирующий текст, без манипулятивных дедлайнов.

### История
- Простые строки/карточки операций с датой, категорией, суммой и типом.
- Фильтры категории и типа; пустые состояния с CTA.
- Никаких багов с отрицательными числами/цветами.

### Задания
- 3–6 осмысленных коротких активностей, сгруппированных по тематике.
- Состояния «можно попробовать», «выполнено», «повторить позже».
- Награды символические: опыт, значок, открытая карточка, но **не выдуманные деньги**.

### Родительская зона
- Чуть спокойнее по цвету, но **визуально тот же продукт**.
- Инсайты без псевдоаналитики: факт операций, недавний прогресс, задания и доступные материалы.
- Рекомендации/FAQ и форма фидбека.
- Любые предполагаемые метрики пометить «по вашим записям»; не заявлять, что это объективные поведенческие исследования.

## 6. Компоненты и библиотеки

**Использовать реальные готовые UI primitives**:
- **shadcn/ui** — Button, Card, Dialog, Drawer, Tabs, Progress, Form, Input, Select, Tooltip, Sheet, Skeleton, AlertDialog, etc.; настраивать, а не оставлять дефолтный bland-UI.
- **Radix UI** — доступные primitives, на которых строятся интерактивные компоненты; не дублировать библиотеки для одного и того же примитива.
- **Motion** (`motion/react`) — переходы между состояниями, появление карточек, прогресс, микроанимации.
- **Lucide React** — единый набор иконок с согласованной толщиной.
- **Sonner** — ненавязчивые уведомления, если это вписывается в стек.
- **React Hook Form + Zod** — аккуратная форма и валидация.
- **Recharts** — только если в спокойной родительской аналитике реально нужен график; **не ради декора**.

Не копируй одну и ту же структуру десятки раз. Предпочитай переиспользуемые компоненты: `SectionCard`, `MoneyAmount`, `SavingsGoalCard`, `ActivityCard`, `TransactionItem`, `EmptyState`, `ParentTip`, `DemoBadge`.

## 7. Motion: живой UI без перегруза

- 120–180ms: hover/press/focus/небольшие изменения состояния.
- 180–280ms: открытие sheet/dialog, перестроение карточки, появление контента.
- 350–650ms: однократная анимация прогресса или «пополнение копилки».
- Типичные easing — мягкие `easeOut` или умеренный spring без избыточного overshoot.
- Числа обновлять плавно, но **не анимировать финансы так, чтобы искажался итог**.
- Допустимые примеры: лёгкое подпрыгивание добавленной монеты; постепенное заполнение полосы цели; аккуратный stagger 40–70ms первых трёх карточек; успешное действие с коротким подтверждением.
- Анимация всегда связана с действием или обратной связью, а не украшением пустого экрана.
- Учитывать `prefers-reduced-motion`; когда включено — отключать декоративные движения, оставлять мгновенное изменение состояния.
- **Никакого постоянного движения** фона, floating shapes, particle field или авто-конфетти.

## 8. Иллюстрации и microcopy

- Мотивы: три отсека, пазлы-персонажи, монеты, цели, простые предметы детского мира.
- Лучше небольшие оригинальные SVG-персонажи/иллюстрации в одном стиле, чем случайные изображения из разных паков.
- Если официальные иллюстрации НЦФГ доступны и разрешены, использовать их в согласованной форме. Не притворяться, что самостоятельно созданные SVG — официальные логотипы.
- Тексты должны быть дружелюбными, но не сюсюкающими; детская мотивация — поддерживающая, без стыда и давления.
- Слова: «Коплю», «Трачу», «Помогаю», «Моя копилка», «Моя цель», «Добавить действие», «Посмотреть прогресс».

## 9. QA интерфейса — обязательный чек-лист перед сдачей

Проверить **в браузере или через доступные автоматические инструменты**, не по памяти:
- [ ] 360 / 390 / 430 / 768 / 1024 / 1440px: нет горизонтального скролла.
- [ ] Карточки/модалки/навигация не перекрываются, кнопки не уходят за экран.
- [ ] На 360px нижняя навигация и sticky-элементы не накладываются на CTA/поля.
- [ ] Кириллица и крупные суммы не обрезаются; длинные подписи переносятся.
- [ ] Загрузки, ошибки, пустые состояния оформлены.
- [ ] Hover, active, keyboard focus, disabled и form-error состояния есть.
- [ ] Цвета категорий согласованы во всех формах/табах/списках.
- [ ] Анимации не вызывают layout shift, jitter или задержку отклика.
- [ ] Reduced motion работает.
- [ ] Контраст и target size соответствуют возрасту аудитории.
- [ ] Нет неоновых эффектов, тяжелых теней, гигантских градиентов, glassmorphism.
- [ ] Нет английских случайных placeholders, lorem ipsum, фиктивных CTA.
- [ ] Детский экран интересный, родительский — спокойный и функциональный.

## 10. Правило качества

Если выбор между очень эффектной статичной картинкой и чуть менее «вау», но **полностью работающим, понятным, живым интерфейсом**, выбирать второй вариант. После этого полировать визуал, пока он не станет действительно приятным. Не останавливайся на дефолтном шадцн-шаблоне: используй его для **основы доступности и поведения**, а собственный стиль — для характерной композиции и ощущения продукта.
